# Journal du 6 octobre 2026 : lancement de myiro-libre

Première journée du projet. Rien n'est encore du code applicatif : la journée a servi à cadrer, documenter et publier les fondations.

## Ce qui a été fait

### Audit et plan d'action
- Audit statique des installations du poste (MY-CT1, FD-S2w, Ergosoft, EIZO ColorNavigator 7, résidus `ProgramData/MYIRO`) : 871 fichiers, 634 Mo, contrôle SHA-256, 84 binaires analysés (`Audit-MYIRO/`).
- Rédaction de `PLAN-ACTION.md` : application Rust libre (GPL-3.0), MYIRO-1 d'abord, FD-9 en parallèle, en 9 phases (fondations, reconstitution de l'ABI de `FDXSDK` puis `FD9SDK`, ponts, essais sur instrument réel, cœur colorimétrique, mires/contrôle/profilage, livraison).
- Début de rétro-analyse : désassemblage Capstone des exports FDX et de leurs appelants (`desassemble.py`, `preuves_abi.py`).

### Constats techniques principaux
- Exports x86 de `FDXSDK` en `__stdcall` (confirmé pour `FDX_GetSDKVersion`, `FDX_Connect`, `FDX_GetDevicePortList`, `FDX_GetMeasureData`, `FDX_Calibration`) ; `FDX_StartMeasurement` reste à trancher.
- Les `libmeasurementdevice*.dll` d'EIZO sont l'appelant de référence pour la séquence de mesure du MYIRO-1 ; `FD-S2w.exe` l'est pour le FD-9.
- `FD9SDK` exige peut-être une clé d'application (`FD-SDK.lic`) : à trancher en phase 2. Ses dépendances x64 manquent dans l'archive.
- Aucun des deux SDK n'expose de création de profil ICC : la chaîne est mesure → CGATS.17 → moteur de profilage séparé.
- Les mires FD-S2w sont du XML lisible, directement importables.

### Décisions d'architecture (`docs/adr/`)
1. **0001** : bibliothèque locale unique plutôt que fichiers épars, avec export/import CGATS.17 et sauvegarde complète.
2. **0002** : ArgyllCMS inclus dans l'installateur, appelé en processus externe (AGPL-3.0 compatible GPL-3.0).
3. **0003** : interface Tauri 2 (cœur Rust, WebView2), bilingue français/anglais.
4. **0004** : le futur RIP libre est un projet distinct qui réutilise des crates partagées (`colorimetrie`, `mires`, formats d'échange).

- Premier commit `5bd17e9` sur la branche `dev` ; `.gitignore` exclut `collecte/`, `SDK/` et tout binaire ou manuel Konica Minolta.

## Règles posées
- Ne jamais appeler les exports `FDX_JIG_*` ni les `FDX_Set*` qui écrivent dans l'instrument tant que leur contrat n'est pas établi.
- Progression sur appareil réel : version SDK → détection → connexion/infos → étalonnage → mesure ponctuelle, avant toute lecture de bande.
- Aucune DLL ni manuel du fabricant n'est redistribué.
- Toujours distinguer « confirmé » et « supposé » dans la documentation.
